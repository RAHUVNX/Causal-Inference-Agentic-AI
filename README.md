# Causal Lift Web Platform

A full-stack web application for computing incremental lift using a two-path causal inference framework. Built with **React**, **Node.js/Express**, and **Python/FastAPI** with PostgreSQL.

## Causal Framework

The platform implements a **two-path counterfactual simulation**:

```
Path A: Suggestion -> Action
Path B: Action -> Outcome (TRX / NBRX)
```

**Incremental lift** is computed as:

```
incremental_action  = predicted_action  - counterfactual_action
incremental_outcome = predicted_outcome - counterfactual_outcome
```

The counterfactual is generated by **zeroing out suggestion features** (setting suggestion_count, percent_other_hcps_suggested, and total_suggestions to zero) and re-predicting through both paths.

## How It Works

| Layer | Technology | Responsibility |
|---|---|---|
| **Frontend** | React + Vite | UI for upload, training config, dashboards, charts |
| **API Server** | Node.js + Express | REST API, CSV parsing, database operations (Prisma) |
| **ML Service** | Python + FastAPI | Feature engineering, Ridge regression, counterfactual simulation |
| **Database** | PostgreSQL | Stores observations, model metadata, lift results |

**Data flow:** React -> Node.js API -> PostgreSQL for storage, Node.js -> Python ML service for computation.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/upload-data` | Upload CSV file, parse and store observations |
| `POST` | `/api/train-models` | Train Path A and Path B models (via Python) |
| `POST` | `/api/run-lift` | Execute full counterfactual simulation (via Python) |
| `GET` | `/api/summary` | Monthly aggregated results and KPIs |
| `GET` | `/api/feature-importance` | Ranked feature importance from trained models |
| `GET` | `/api/health` | Health check (Node.js + Python service status) |

## Database Schema

- **observations** - Raw HCP-month observation records from CSV uploads
- **model_metadata** - Trained model coefficients, feature lists, scaler states
- **model_runs** - Training/simulation run history with status tracking
- **lift_results** - Per-HCP-month predicted, counterfactual, and incremental values
- **feature_importance** - Ranked feature importance from each trained model

## Setup

### Prerequisites

- **Node.js** 18+
- **Python** 3.10+
- **PostgreSQL** 14+

### 1. Database Setup

Create a PostgreSQL database:

```bash
createdb causal_lift_db
```

### 2. Python ML Service

```bash
cd python_service
python -m venv venv
source venv/bin/activate        # On Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 5001 --reload
```

The ML service runs on http://localhost:5001.

### 3. Node.js Backend

```bash
cd server
cp .env.example .env
# Edit .env with your DATABASE_URL if needed
npm install
npx prisma migrate deploy
npx prisma generate
npm run dev
```

The API server runs on http://localhost:4000.

### 4. React Frontend

```bash
cd client
npm install
npm run dev
```

Open http://localhost:3000 in your browser.

## CSV Format

Upload a CSV with these columns:

| Column | Required | Type | Description |
|---|---|---|---|
| `hcp_id` | Yes | string | Healthcare professional identifier |
| `month` | Yes | date | Observation month (YYYY-MM-DD) |
| `suggestion_type` | Yes | string | Type of suggestion (e.g., "email") |
| `action_type` | Yes | string | Type of action (e.g., "detail") |
| `outcome_type` | Yes | string | "trx" or "nbrx" |
| `suggestion_count` | Yes | number | Number of suggestions |
| `action_count` | Yes | number | Number of actions taken |
| `outcome_count` | Yes | number | TRX or NBRX value |
| `specialty_code` | No | string | HCP specialty |
| `region_code` | No | string | Geographic region |
| `tenure_months` | No | number | HCP tenure in months |
| `prior_trx` | No | number | Prior period TRX |
| `prior_nbrx` | No | number | Prior period NBRX |
| `total_suggestions` | No | number | Total suggestions received |
| `theme` | No | string | Suggestion theme for theme-level analysis |

## Usage Flow

1. **Upload Data** - Upload your CSV observation data
2. **Train Models** - Configure filter triangle and train Path A + Path B
3. **Run Lift Simulation** - Execute counterfactual simulation and view incremental lift
4. **Dashboard** - View KPIs, charts, and monthly summaries
5. **Model Metrics** - Inspect R², MAE, feature importance rankings

- **Backend API:** Node.js, Express, TypeScript, Prisma ORM, Zod validation
